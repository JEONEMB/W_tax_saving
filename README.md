# WON 세금비서 MVP

은행이 이미 보유한 고객·계좌·거래 정보를 활용해 절세 후보를 찾고, 필요한 추가 정보에만 동의를 받아 Agent가 개설·납입·장려금 신청을 진행하는 체험 앱입니다. **기관 조회와 금융 실행·정부 신청은 가상 데이터로 시연합니다.**

## 실행

Node.js 22.12 이상, Python 3.11 이상을 사용합니다. Windows PowerShell:

```powershell
cd W_tax_saving
npm.cmd install
npm.cmd run setup:server
npm.cmd run dev
```

최초 설치 후에는 `npm.cmd run dev`만 실행하면 됩니다. Vite 주소는 기본 http://127.0.0.1:5173, API는 http://127.0.0.1:8000입니다. Ctrl+C로 함께 종료합니다. `vite`을 찾지 못하면 프로젝트 폴더에서 `npm.cmd install`을 먼저 실행하세요.

현재 은행 체험 화면만 실행하려면 `npm.cmd run dev:ui`를 사용합니다. 이 화면은 브라우저 저장으로 동작하므로 Python 서버가 필요하지 않습니다.

## 현재 사용 흐름

1. 오른쪽 리모컨 또는 모바일 상단 조절 버튼에서 고객을 선택합니다.
2. 홈의 **내 절세 혜택 찾기**를 누르면 은행의 고객·금융 정보로 여러 후보를 추천합니다.
3. 후보를 선택하면 이미 확인한 정보와 Agent의 실행 계획을 보여줍니다.
4. 타행 계좌·주거·가구 소득·재산 등 필요한 추가 자료만 조회 목적과 항목을 제시하고 동의를 받습니다. 가상 연계 자료로 자동 채우며, 조회되지 않은 정보만 질문합니다.
5. 실행 내용에 별도로 동의하고 모의 인증을 하면 계좌 개설·납입 또는 장려금 모의 신청을 처리합니다.
6. 실행 결과·계좌·잔액·동의 상태를 고객별로 저장합니다. 지연 시 재실행 대신 결과 조회로 이어집니다.

별도의 샘플 선택·직접 입력용 `diagnosis` 화면은 제거했습니다. 이전 `/#diagnosis` 주소는 홈을 표시합니다.

## 대표 시연

| 리모컨 고객 | 시연 |
|---|---|
| 연금에 더하는 절세 | 기존 연금 납입 300만원 확인 → 타행 납입 조회 동의 → 생활비 여부 확인 → 200만원 추가 납입 동의·인증 → 잔액 반영 |
| 첫 연금계좌 만들기 | 은행 고객정보로 개설 → 별도 추가 조회·납입 동의 → 납입 |
| 주식은 하는데, ISA는? | 기존 투자 선호 반영 → 타행 ISA·가입 조건 조회 → 증권사 연계 동의·인증 → 모의 개설 |
| 내 집을 위한 첫걸음 | 청약 중복 보유 확인 → 모의 개설 → 납입 |
| 월세도 놓치지 않도록 | 반복 이체 12건 확인 → 계약·주소 조회 동의 → 증빙 준비 보고서 |
| 모르면, 함께 확인해요 | 미확인 외부 정보·예산 부족 조건에서 실행 차단 |
| 근로장려금 신청 준비 | 은행 고객·수령계좌 미리 채움 → 가구 소득·재산 조회 동의 → 신청 동의·인증 → 모의 접수 내역 |
| 자녀장려금도 챙기기 | 부양자녀 포함 자료 확인 → 별도 동의·인증 → 모의 접수 내역 |

리모컨의 응답 시뮬레이션으로 정상·실패·결과 지연을 재현합니다. 계좌 개설과 납입은 별도 실행이며, 계좌 개설만으로 공제액이 생기지 않습니다. 은행 입금액·잔액을 가구 전체 소득·재산으로 간주하지 않습니다.

이전에 개설한 ISA는 새로고침 후에도 유지되며, 상세 화면에서 **개설 결과 보기**로 이동합니다. 처음부터 다시 시연하려면 리모컨 상단의 **이 고객 시나리오 다시 시작**을 선택하세요. 확인 후 선택 고객의 가상 계좌·응답·실행내역만 초기화하며, 다른 고객 내역은 유지합니다. 모바일에서는 상단 조절 버튼으로 리모컨을 엽니다.

## 코드와 저장

- `src/App.tsx`, `BankHome.tsx`, `Discovery.tsx`: 홈·추천·리모컨·실행내역.
- `src/bank-context.ts`: 은행 보유 정보와 동의 후 조회하는 가상 외부 자료.
- `src/AgentJourney.tsx`, `domain.ts`: 추가 정보 확인·금융 실행 조건·동의·개설·납입.
- `src/GrantAgentFlow.tsx`, `grants.ts`: 장려금 자동 채움·신청 조건·별도 동의·모의 접수·지연 복구.
- `src/journey.css`: 홈 버튼·한글 줄바꿈·정보 카드·모바일 스타일.
- `src/BankResult.tsx`, `GrantResult.tsx`, `results.css`: 은행 업무별 결과·국세청 신청 접수 화면. 큰 제목은 개설·납입·접수 완료로 표시하고, 체험 여부는 상단 배너와 결과 하단에서 안내합니다. 실제 계좌나 공식 접수증은 아닙니다.
- 현재 화면의 브라우저 저장 키: `won-demo-v1`, 선택 고객: `won-selected`.

현재 화면의 Agent는 규칙과 모의 연계로 동작합니다. 실제 은행·마이데이터·국세청 API 또는 LLM에 연결되어 있지 않습니다.

이전에 추가한 `backend/`의 FastAPI/Pydantic/SQLite API, `shared/` 규칙, `src/mvp/` 계산·문서 처리 모듈은 별도로 유지합니다. **현재 은행 체험 화면에는 이 API·OCR·선택적 LLM을 연결하지 않았습니다.** 이전 직접 입력 UI에서 제공하던 CSV/JSON 입력·OCR·과제 저장은 현재 화면에 노출하지 않습니다. API 계약은 서버의 `/docs`에서 확인할 수 있습니다. 서버 기본 DB는 `backend/data/won.sqlite3`입니다.

선택적 LLM 서버 설정은 `.env.example`을 참고하세요. 서버 키는 `VITE_` 변수나 Git에 넣지 않습니다. 키 없는 경로와 모의 응답은 검증했으며 실제 유료 호출은 검증하지 않았습니다.

## 검증

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run test:server
npm.cmd run test:e2e
```

서버 및 Python/TypeScript 계산 비교 테스트에는 `setup:server`가 필요합니다. 브라우저 테스트는 Microsoft Edge와 격리된 포트 5187/8017을 사용합니다. 홈의 320px·390px·데스크톱 레이아웃, 고객별 추천, 추가 조회와 실행 동의 분리, 개설·납입, 실패·지연·새로고침 복구, 장려금 모의 접수를 검증합니다.

명세와 현재 구현의 차이는 [구현 현황](IMPLEMENTATION_STATUS.md)을 참고하세요.
