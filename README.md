# WON 세금비서

은행이 가진 금융정보와 고객의 추가 확인을 연결해 **발견 → 질문 → 동의 → 모의 실행 → 결과 확인**까지 체험하는 프론트 MVP입니다. 실제 은행 연계, 금융거래, 투자 주문, 본인인증, 세금 신고는 하지 않습니다.

## 화면 개편과 개설 버튼 수정

첨부된 WON 화면을 참고해 심볼 중심의 시작 화면, 회색·하늘색 배경, 둥근 자산 카드와 반원 그래프를 적용했습니다. 홈에서 아래 화살표로 자산 요약에 이동하고 금액 표시를 켜고 끌 수 있습니다. `public/won-logo.svg`는 첨부 로고를 참고해 재현한 벡터이며 원본 이미지 파일은 아닙니다.

기존에는 모든 질문의 `no` 응답 및 세금 공제 미충족이 계좌 개설까지 차단했습니다. 이제 `executionReadiness`가 개설 조건과 공제·납입 조건을 분리합니다. 첫 연금계좌의 개설은 가입 확인으로, 청약 개설은 중복 계좌·가입 확인으로 판단하며 공제 및 추가 납입은 별도로 확인합니다. ISA의 근로소득 유무는 가입 필수 요건으로 사용하지 않습니다. 미확인 가입 요건·중복 계좌·동의 누락은 계속 차단합니다.

각 질문에는 이번 실행의 필수 여부를 표시하고, 부정 응답의 의미와 버튼이 비활성화된 사유를 버튼 근처에 보여줍니다. 질문 응답은 최신 고객 상태를 기준으로 누적해 빠르게 연속 선택해도 이전 응답을 덮어쓰지 않습니다.

## 실행

다른 PC에서 이어서 작업하려면 다음과 같이 저장소를 복제합니다.

```sh
git clone https://github.com/JEONEMB/W_tax_saving.git
cd W_tax_saving
npm ci
npm run dev
```

Windows PowerShell에서 `npm` 실행이 차단되면 `npm.cmd`로 바꾸세요. 소스·원본 명세·테스트·패키지 잠금 파일은 저장소에 포함되며, 의존성과 빌드 결과는 각 PC에서 생성합니다. 고객별 시연 진행 상태는 해당 브라우저의 로컬 저장소에 있으므로 Git으로 옮겨지지 않으며, 새 PC에서는 기본 시연 고객으로 시작합니다.

Node.js 22.12 이상(개발 환경 24)을 사용합니다. Windows PowerShell에서는 실행 정책과 충돌하지 않는 `npm.cmd`를 사용하세요.

```powershell
npm.cmd install
npm.cmd run dev
```

터미널에 표시되는 로컬 주소(기본 `http://127.0.0.1:5173`)를 엽니다. API 키와 환경변수는 필요하지 않습니다. Google Fonts를 사용할 수 없으면 시스템 글꼴로 표시됩니다.

```powershell
npm.cmd run build
npm.cmd test
npm.cmd run test:e2e
```

브라우저 테스트는 설치된 Microsoft Edge를 사용하며 로컬 서버를 자동으로 시작·종료합니다. 다른 운영체제에서는 `playwright.config.ts`의 `channel`을 설치된 브라우저에 맞게 변경하세요. 빌드 결과는 `dist/`에 생성됩니다.

## 시연 방법

전체 목표 명세와 현재 구현의 차이는 [구현 현황](IMPLEMENTATION_STATUS.md)에 정리했습니다. 원본 명세의 모든 기능이 완료된 것은 아닙니다.

PC 오른쪽 패널 또는 모바일 상단의 조절 아이콘에서 고객을 선택하세요. 홈 → 맞춤 기회 → 샘플 데이터 조회 동의 → 조건 확인 → 실행안 → 실행 동의 → 모의 인증 → 모의 실행 순서로 진행합니다.

| 고객 | 체험 |
|---|---|
| 김우리 | 기존 연금저축 300만원에 200만원 추가 납입. 국세 공제 계산액 차이 30만원, 잔액 842만원 → 642만원 |
| 이시작 | 연금계좌 개설 후 **새로운 동의**로 추가 납입. 개설만으로 입출금 잔액은 변하지 않음 |
| 박투자 | 국내 주식 직접 투자 선택 → 외부 증권사 중개형 ISA 체험. 별도 외부 정보 제공 동의 필요. 신탁형 선택 시 우리은행 체험 경로 |
| 정내집 | 청약계좌 개설 → 별도 동의로 20만원 첫 납입 |
| 최월세 | 주소·표준 자격·자료 준비 확인 → 국세 공제 계산액 122만 4천원 → 샘플 증빙 보고서 다운로드 |
| 한확인 | 미확인 응답으로 실행 보류. 확인 후에도 예산 0원에서는 추가 납입 불가. 데이터 화면에서 가용 예산 수정 가능 |
| 윤도움 | 근로장려금: 별도 정보 이용 동의 → 은행 자료 정리 → 가구·소득·재산·기신청 확인 → 준비서 생성 → 공식 경로 안내 |
| 장가족 | 자녀장려금: 위 흐름에 적격 부양자녀 확인 추가. 계좌 개설·국세청 신청 접수는 하지 않음 |

장려금의 정상 시연 예: 윤도움은 단독가구·근로소득·부부합산 총소득 1,800만원·가구재산 1억원·전체 재산 확인·제외 요건 없음·미신청·안내문 없음으로 선택합니다. 장가족은 홑벌이가구·총소득 3,200만원·가구재산 1억원에 표준 요건의 부양자녀 있음을 확인합니다. 모두 **가상 고객의 시연 응답**이며 실제 고객에게 적용되는 자동 결론이 아닙니다.

장려금은 2025년 소득에 대한 2026년 신청을 다루며 현재 시연 기준일은 2026-10-17입니다. 기존 여섯 고객은 2026년 절세 시나리오입니다. 날짜·기신청·자료 부족·조건 불충족을 확인할 수 있고, 신청 준비서 다운로드 후 홈택스에서 직접 진행할 단계가 표시됩니다. 공식 사이트에는 정보를 전송하지 않습니다.

**실패 시연:** 응답 시뮬레이션을 ‘납입 실패’로 설정합니다. 개설은 완료되고 납입만 실패합니다. ‘정상 처리’로 변경하고 납입을 다시 준비하면 기존 계좌에 한 번만 반영됩니다.

**지연 시연:** ‘결과 확인 지연’에서 실행하면 잔액을 즉시 변경하지 않고 결과 확인 필요 상태를 저장합니다. 새로고침 후 ‘실행 결과 조회’로 한 번만 반영합니다. 미확정 실행이 있는 동안 새 실행은 차단됩니다.

**이어하기:** 진행 중 화면에서 보류하거나 다른 탭으로 이동한 뒤 실행내역에서 이어갑니다. 동의는 실행 내용에 종속됩니다. 금액·자격·데이터를 수정하면 다시 동의·인증해야 합니다.

## 구조

- `src/domain.ts`: 가상 고객, 출처, 질문, 계산, 실행 가드와 상태 전이. `analyze / answerQuestion / previewAction / approveAction / executeAction / getActionResult` 인터페이스.
- `src/grants.ts`, `src/GrantFlow.tsx`: 정부지원 신청 준비 규칙·동의·은행 샘플·신청 준비서·단계별 화면. `src/session.ts`: 기존 저장 데이터 보존 및 신규 고객 추가.
- `src/App.tsx`: 혜택·Agent·실행내역·데이터·실행 화면과 로컬 저장. `src/BankHome.tsx`: 개편한 시작·자산 화면. `src/style.css`와 `src/bank-theme.css`: 반응형 화면 및 WON 참고 테마.
- `src/domain.test.ts`: T01~T12의 지원 범위와 계산·동의·중복·실패·지연 회귀 테스트. `e2e/`: 실제 브라우저 사용자 여정.

고객별 상태는 브라우저 `localStorage`의 `won-demo-v1`에 저장됩니다. 외부로 금융정보를 전송하지 않습니다. 고객 초기화·전체 초기화가 제공됩니다. 모든 고객은 연중 근로·다른 합산소득 없음 등의 **표준 가상 사례**입니다. 실제 고객의 모든 적격 조건을 판정하는 엔진은 아닙니다.

## 금액과 출처

소득공제, 국세 세액공제 계산액, 비과세 한도를 분리합니다. 실제 환급은 최종 세액과 기납부세액 등이 필요하므로 계산하거나 보장하지 않습니다. 타행 연금 납입이 있거나 모르면 구체 금액 입력을 지원하는 대신 전문 확인 상태로 보류합니다. 자녀 있는 카드 사례, 비표준 월세, 다른 귀속연도는 지원 범위 밖입니다.

직접 확인한 주요 공식 자료:

- [국세청 연금계좌 공제 안내](https://webtv.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7875&mi=6439)
- [국세청 월세 공제 안내](https://sc.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=239025&mi=40613)
- [우리은행 신탁형 ISA 안내](https://spot.wooribank.com/pot/Dream?withyou=IMISA0044)
- 나머지 항목의 관련 법령 링크는 혜택 상세에 표시합니다. 원본 명세의 2026년 규칙은 **샘플 규칙**으로 관리하며 전면적인 세법 검수 완료를 의미하지 않습니다.

T08·T09의 모집 종료 규칙은 원본 문서의 고정 fixture를 검증하며 실제 신규 모집 가능 여부를 안내하는 UI에는 사용하지 않습니다. 거래 중복·취소 제외는 규칙 함수 수준으로 검증합니다. 거래 업로드와 자유 입력된 실제 거래 분류, 외부 세무 데이터 연결은 구현 범위 밖입니다.

ISA는 은행 신탁형과 증권사 중개형을 구분하며, 특정 증권사와의 제휴를 주장하지 않습니다. 계좌 개설 시연은 의무 유지기간·상품별 약관을 모두 재현하는 실제 가입 절차가 아닙니다. 월세 보고서는 생성 당시의 샘플 데이터를 보존하며 공식 은행 증명서가 아닙니다.

## 구현 경계

Agent는 API 없는 규칙형 시뮬레이터입니다. 조건·계좌·잔액·예산에 따라 질문과 실행 경로가 바뀌며, 자유 입력은 근거·다음 행동 등의 제한된 의도를 안내합니다. LLM, FastAPI, SQLite는 사용하지 않습니다. 프론트의 동의·가드·감사 이력은 시연 목적이며 실제 거래에 필요한 서버 권한 검증을 대체하지 않습니다.

고객 정보·완료 이력은 고객별로 유지되고 시뮬레이션 응답 모드는 새로고침 시 정상 처리로 돌아옵니다. 배포는 수행하지 않습니다.

## AIBEE 맞춤 발견 흐름

홈의 ‘절세 시작하기’ → 약 3.3초의 AIBEE 분석 체험 → 고객별 추천 목록 3개 → 선택한 상품·지원 상세로 이어집니다. 시연 컨트롤은 고객을 바꾸고 홈으로 돌아오며, 자동으로 상품 상세를 열지 않습니다. 추천 목록은 현재 보유 계좌·예산·완료 이력을 반영합니다. 추천은 가상 고객 시나리오의 확인 후보이며 가입·공제·지원 적격 확정이나 실제 AI/외부 조회 결과가 아닙니다.

분석 중 이탈하면 타이머를 해제합니다. 상세에서 뒤로 가면 추천 목록으로 돌아오며, 추천 화면 새로고침에도 현재 고객 기준 목록이 복원됩니다. 동작 줄이기 설정에서는 캐릭터 애니메이션을 끕니다.
