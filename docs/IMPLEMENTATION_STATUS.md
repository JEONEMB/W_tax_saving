# 구현 현황 · 2026-10-19

사용자의 수정 요청에 따라 **은행 보유 정보 → 한 번의 추천 요청 → 필요한 추가 자료 동의 → Agent 실행**을 주 사용 흐름으로 변경했습니다. 별도 `diagnosis` 시작·직접 입력 화면은 제거했습니다. 원래 명세의 모든 항목이 현재 화면에 통합된 상태는 아닙니다.

## 현재 화면에서 동작하는 범위

| 범위 | 구현 |
|---|---|
| 홈 | 한 개의 주요 버튼, 한글 줄바꿈·버튼 크기 수정, 모바일 320px/390px 검증 |
| 리모컨 | 8개 가상 고객 전환, 고객별 상태 저장, 정상·실패·지연 응답 선택 |
| 추천 | 고객별 보유 계좌·납입·거래 특성을 반영한 후보와 다음 행동 |
| 은행 보유 정보 | 고객 확인·잔액·납입·월세 후보·투자 선호·급여 추정 입금 표시, 재입력 생략 |
| 추가 정보 | 목적·조회 항목별 동의, 모의 기관 조회 후 자동 반영, 미확인 정보만 최대 3개 질문 |
| 금융 실행 | 개설과 납입 분리, 실행별 동의·모의 인증, 예산·잔액·조건 확인, 중복 방지·지연 결과 조회 |
| 업무별 결과 | 연금·ISA·청약 개설 내역, 납입 거래명세, 월세 증빙 준비 결과, 국세청 장려금 접수 내역으로 구분. 처리 당시 계좌·금액·시각을 저장해 후속 납입에도 이전 명세 유지 |
| 월세 | 은행 반복 이체와 동의한 계약·주소 모의 자료 대조, 샘플 증빙 보고서 다운로드 |
| 장려금 | 은행 정보 자동 채움, 동의 후 가구·소득·재산·자녀 모의 자료 반영, 신청 동의·인증, SIM 번호 모의 접수·다운로드 |
| 저장 | 브라우저에 고객별 금융 상태·응답·동의·실행내역 저장, 새로고침 복구 |
| 철회·변경 | 추가 정보 동의 철회, 변경 시 실행 승인 무효화, 장려금 지연 중 정보 변경 시 재확인 |

은행 기록과 외부 자료는 구분합니다. 특히 은행 급여 입금액·자행 잔액으로 가구 총소득·전체 재산을 채우지 않습니다. 가상 기관 자료가 없는 고객은 미확인으로 남깁니다. 투자 선호가 은행 기록에 있는 고객은 같은 질문을 다시 하지 않습니다.

장려금은 신청 준비서 생성에서 **모의 신청 접수**까지 확장했습니다. 실제 국세청 전송·접수·심사·지급은 이루어지지 않습니다. 계좌 개설·납입 역시 실제 금융거래가 아닙니다.

## 유지한 모듈과 통합하지 않은 범위

- `backend/`의 FastAPI·Pydantic·SQLite, `shared/` 규칙·샘플, `src/mvp/` 계산·문서 처리 모듈은 유지합니다.
- 현재 은행 화면은 `domain.ts`·`grants.ts` 및 브라우저 저장을 사용합니다. 서버 진단·과제 저장 API, 선택적 LLM, OCR, CSV/JSON 입력은 이 흐름에 아직 통합하지 않았습니다.
- 제거한 직접 입력 화면의 기능을 현재 앱에서 사용할 수 있다고 안내하지 않습니다. 현재 Agent는 규칙과 모의 연계로 실행합니다.
- 원 명세의 지원제도 전체 카탈로그·모집 알림, 실기관 API, 운영 인증·감사로그·정책 관리, 비표준 세무 사례 전체 검수는 완성되지 않았습니다.
